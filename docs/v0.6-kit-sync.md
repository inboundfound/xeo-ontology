# XEO 0.6.0 "kit sync" — review guide

Branch `jamesmthornton/v0.6-kit-sync`, based on `a76c1e8` (0.5.0).

## What this is

`xeo-graph-kit` is gaining three courses (Graphs 101, 201, 301) and now uses XEO's names for
everything it teaches. The contract between the two repositories is the kit's
`docs/learn/GRAPH-MODEL.md`. This release makes XEO's side of that contract true:

1. it adds every term the contract marks NEW;
2. it widens or fixes the existing terms the contract uses in a way the ontology did not allow;
3. it generates a Neo4j profile from the Turtle, so the kit can check itself against XEO
   mechanically;
4. it adds SHACL shapes, worked examples and a validator, so XEO can check itself.

| | 0.5.0 | 0.6.0 |
|---|---|---|
| Classes | 36 | 45 |
| Object properties | 61 | 91 |
| Datatype properties | 65 | 95 |
| Reference schemes | 20 | 29 |
| Concepts | 93 | 146 |
| Modules | 8 | 9 (`xeo-analysis.ttl` is new) |

## How to review it

1. Read **Consumer impact** below first. It is the only part that touches existing terms.
2. Skim the term tables. Each new term's full definition is in its module, under the
   `# --- v0.6.0 (kit sync)` banner at the foot of the file.
3. Read the header of `xeo-analysis.ttl`. It states a position, and it is the part most worth
   disagreeing with.
4. Read **Where this differs from GRAPH-MODEL.md**. Those are changes the kit has to make.
5. Run the validator:

```bash
uv run --no-project --with rdflib --with pyshacl python tools/validate.py
```

## Consumer impact: none breaking

No term IRI was renamed or removed. No domain or range was narrowed. All 299 subjects declared
on `main` are still declared, with their types unchanged.

`launch-guardian` and `if-control-center` cite these files by line number. Every in-place
change below replaced exactly one line with one line, and every new term is appended below the
existing text, so no declaration moved. Their 33 line citations and 110 term references
resolve exactly as before (25 citations OK and the same 8 that were already wrong on `main`).

### Every domain or range that changed

All eleven are removals. Removing an `rdfs:domain` or `rdfs:range` removes an entailment and
nothing else, so no existing data changes meaning.

| Property | File:line | Removed | Reason |
|---|---|---|---|
| `embeddingRef` | `xeo-core.ttl:166` | domain `Term` | any embedded node carries it |
| `embeddingModel` | `xeo-core.ttl:172` | domain `Term` | same |
| `onEngine` | `xeo-visibility.ttl:73` | domain `LLMResponse` | a SerpSnapshot is on an engine |
| `capturedAt` | `xeo-visibility.ttl:103` | domain `LLMResponse` | **bug:** SerpSnapshot carries it |
| `model` | `xeo-visibility.ttl:107` | domain `LLMResponse` | **bug:** `inTopic` carries it |
| `occurredAt` | `xeo-engagement.ttl:77` | domain `ConversionEvent` | ExternalEvent carries it |
| `assessedAs` | `xeo-decision.ttl:120` | domain `Tactic` | production scores the Recommendation |
| `verdict` | `xeo-decision.ttl:214` | domain `Gap` | Feedback carries a verdict |
| `includes` | `xeo-strategy.ttl:80` | domain `Playbook` | a Framework includes the same things |
| `activates` | `xeo-strategy.ttl:85` | range `Playbook` | a Framework is activated the same way |
| `statement` | `xeo-strategy.ttl:108` | domain `Practice` | **bug:** Gap, Recommendation, Objective carry it |

The three marked **bug** were asserting something false. `rdfs:domain` is an entailment rule:
with `capturedAt` domain-locked to `LLMResponse`, every `SerpSnapshot` that carried a capture
time was inferred to be an LLM response.

`occurredAt`, `verdict` and `statement` are not in the brief. They are the same defect, and
the new terms would have triggered it (an `ExternalEvent` typed as a `ConversionEvent`, a
`Feedback` typed as a `Gap`).

Where the old domain is still the usual case, it is kept as a hint
(`xeo:domainIncludes`), which entails nothing.

### Descriptions edited in place

One line each, same line number: `Topic`, `linksTo`, `hasResult`, `embeddingRef`, `name`,
`resultType` (core); `onEngine`, `model` (visibility); `assessedAs`, `verdict` (decision);
`includes`, `activates` (strategy). Each edit adds the new case and removes nothing. The
hosting comment at `xeo-core.ttl:8` and the eight `owl:versionInfo` lines also changed in
place.

### Triples added to existing terms

Appended at the foot of each module, as extra statements about a term declared above:

- an `rdfs:label` for all 126 existing properties (none had one);
- a `dct:description` for the 23 terms that lacked one, and an `xeo:epistemicLayer` for the 9
  that lacked one (the `Engine` and `ConversionPoint` subclasses, `origin`, `address`);
- `appliesToConcept rdfs:subPropertyOf appliesTo`, and
  `appliedPractice rdfs:subPropertyOf evaluatedPractice`;
- `domainIncludes` / `rangeIncludes` hints on `evidencedBy`, `assessedAs`, `verdict`,
  `includes`, `activates`, `statement`, `inScope`.

The shapes are conservative. Each checks one rule a term's description already makes, and none
closes a class. What they check: `confidence`, `similarity`, `mentionRate` and `citationRate`
are between 0 and 1; a `magnitude` has a `magnitudeUnit` and the reverse; a `URL` has one
`address`; a `Domain` has one `name`; a `SerpSnapshot` has `capturedAt`; an `LLMResponse` has
`capturedAt` and `model`; a `MetricTarget` has one `metric` and a `direction` of `up` or
`down`; an `Outcome` has one `result`; a `Practice` has a `statement`, one `practiceKind` and
one `status`; a `Stage`'s `stageOrder`, when present, is one integer; an `AlgorithmRun` has
one `algorithm` and a `projection`.

## Where this differs from GRAPH-MODEL.md

Places where the contract asked for something XEO's conventions do not allow, or left
something out. The convention-respecting thing was done. Each needs a matching change, or a
decision, on the kit side.

1. **Fetch observations belong on the `FETCHED` edge, not the `URL` node.** The contract puts
   `title`, `statusCode`, `indexable`, `wordCount`, `crawlDepth`, `h1` and `contentType` on
   `(:URL)`. XEO's rule, which lesson 101 itself teaches, is that the address lasts and the
   rest is what one crawl saw. The new slots say "carried on fetched". A copy on the node is
   allowed as a cache of the latest crawl and should say which crawl it came from.
2. **Five of the crawl slots are derivations, not observations**: `indexable`, `wordCount`,
   `crawlDepth`, `contentHash`, `linkPosition`. Each is a crawler's computation with no
   primary standard behind it. The kit's `layer` stamp for them should be `derivation`.
3. **`layer` is not an XEO term.** The contract says every node and relationship carries
   `layer`. XEO types terms with `xeo:epistemicLayer` and has explicitly not decided to own an
   instance-level property (`xeos:epistemicLayer` says so). The profile records `layer` as a
   convention (`conventions.layerKey`) and gives the value for each label and type. No
   `xeo:layer` was minted.
4. **Property keys the contract uses that XEO does not declare, and that are not marked NEW**:
   `path` (URL), `code` (Diagnostic), `level` (on `REQUIRES_CAPABILITY`), `hypothesis`
   (Experiment), and the surrogate `id`. None was added: they were not asked for, and `level`
   has no stated meaning to define. The kit's alignment check will report them. Either put
   them on the kit-local list or propose them for 0.7.
5. **Concept slots come in two forms.** `algorithm`, `basis`, `frameworkKind` and
   `organizationKind` are object properties to a `skos:Concept`, the idiom of `gapType` and
   `execution`. The contract stores each as a code on the node or edge. Both are conformant,
   and the profile lists each slot as a relationship type and as a property key
   (`"conceptSlot": true`).
6. **`sentiment`, `linkPosition` and `device` are controlled strings, not concept ranges.**
   The brief called `sentiment` a concept slot. Core and visibility stand alone on primary web
   standards and take no SKOS dependency, so they follow `resultType`: a string code with a
   published scheme. For the kit this changes nothing.
7. **`Gap {magnitude}` needs `magnitudeUnit`.** The contract's Gap carries a magnitude and no
   unit. XEO's rule (now a shape) is that a magnitude never travels alone.
8. **`Feedback {verdict}` reuses `xeo:verdict`** with its domain opened, and its values are
   the `feedbackVerdict` scheme. `Gap {statement}` and `Recommendation {statement}` reuse
   `xeo:statement` the same way.
9. **`suggests` is a norm, `atStage` is a norm.** The contract does not give layers for them.
   A diagnostic's usual response is a standing claim about a class of cases.
10. **`communityId` is an integer**, and `parameters` is one serialized JSON string.
11. **`Entity` is a hazardous name.** It collides in conversation with the epistemic layer
    `entity`. It was added as asked, and its description says which sense it means.

## Deliberately not decided

| Question | Why it is open |
|---|---|
| **Placement** (PRD call 4) | Still Jim's. The kit keeps `Placement` kit-local. Nothing here models it. |
| **Tenancy key** (PRD call 5) | `websiteId` stays the only tenancy key. `Organization` adds a party, not a second key, and no `organizationId` was added. |
| **A `Metric` class** | Awaiting the metrics and KPIs research brief. `metric` stays a controlled string; `mention_rate` and `citation_rate` were added to the existing scheme and no more. |
| **The CRM layer** | Awaiting its brief. `Organization` is explicitly not a CRM mirror, and `crmRecordRef` stays the join. |
| **`seovoc` alignment** | Open work, unchanged. `xeo-align.ttl` still bridges only schema.org, PROV-O and SKOS. |
| **Content negotiation on xeoontology.org** | Not in place. Term IRIs return HTML. The README no longer claims otherwise. |
| **Republishing the site** | The xeoontology.org site repository needs a manual republish of the new and changed files: `xeo-analysis.ttl`, the eight changed modules, `context.jsonld`, `schemes.json`, `xeo/index.html`, `neo4j-profile.json`, `context.neo4j.jsonld`, `shapes/xeo-shapes.ttl`. Until then the new term IRIs do not resolve. |
| **`owl:versionIRI` / `owl:priorVersion`** | Not added. A version IRI should resolve, and the site serves no versioned paths. Adding one that 404s is worse than having none. |
| **An instance-level layer property** | See item 3 above. |
| **Are `mentionRate` and `citationRate` observations?** | They are marked `observation`. By the convention that a computed rate is a derivation, they are not. Changing a layer changes what a consumer's filter returns, so it was left for a decision. |
| **24 existing observation terms name no `groundedIn`** | The validator lists them as a note. Some have no primary contract and may be mislabelled; that needs a term-by-term pass. |
| **Consumers still cite `weo:`** | `launch-guardian` and `if-control-center` on `origin/main` still write `weo-decision.ttl:N` and `weo:Term`. The stock `tools/verify_citations.py`, which looks for `xeo`, finds nothing in them. The check for this release was run with the patterns switched to `weo`. The consumers need the rename, or the checker needs to accept both. |
